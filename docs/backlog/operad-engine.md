# operad-engine：flow 引擎

- 状态：idea（方向已定：做；节点类型清单与持久化细节未定）
- 涉及 ADR：0048、0001、0040、0011
- 来源：`operad.md`；`research/2026-11-04-agent-autoloop.md`「内核与测试」；`research/2026-11-05-noop.md`「架构」

## 背景

今天 arc 的任务生命周期是写死的一条流程，`[flows]` 只能换参数。要的是一张能设置的 graph：节点是步骤，边是结果，任何一个节点可以指向一个本地 TS 文件做定制。节点会跨天（等人、等 CI、定时复查），所以引擎必须事件溯源、可续跑、幂等。agent-autoloop 的内核（`decide` 纯函数、`evolve` 单写者、追加日志、`why` 查一轮）和 pi durable 的检查点（每个步骤一个可恢复的状态机、`replay: safe` 才重跑）是两份可对照的先例。

## 决定（已定）

1. flow 是一个 TS 模块，默认导出 `defineFlow(...)` 的值：步骤、边、每一步的种类和参数（数据），步骤的定制逻辑是 TS 文件。引擎内部把这个结构叫 graph。
2. 引擎是事件溯源的：每次被接受的输入产生一批事实，状态从日志算出（内部是纯函数 decide 和 evolve，不对用户暴露）；用户在“历史”里看到每一步和它的原因；日志从不存密钥。
3. 节点声明可重放与否；崩溃后可重放的节点重跑，不可重放的给下游一个"被打断"的结果；连续崩溃到上限就停住等人。
4. 内核只有四种基本步骤：调用插件的一个步骤、等人（结束本轮，答案是事件，出现在待处理里）、等待（定时或 `wait_check` 条件）、结束。跑命令、跑检查、跑 harness、发通道、落地都是插件提供的步骤。并行与汇合以后再加。
5. 今天的 arc 流水线（worker → commands → mutation → review → ci → human → integration）由 `dev` 插件表达为第一个 flow，现有行为测试当它的验收规格。插件可以从项目的 JSON 配置生成 flow（`dev` 把 `.operad/dev.json` 的 stage 列表编译成 `defineFlow` 的值，见 `operad-dev-flows.md`）；生成的 flow 和 TS 写的 flow 在引擎里没有区别。
6. 幂等与熔断进核心：同一来源同一编号的事件只记一次；事件引发的事件带跳数，上限之外只记录不派发；一个 flow 的一次运行连续失败到上限不再重试。
7. 同一个 flow 同一个对象一次只有一个运行。
8. 存储是可换的后台：日志接口加一份一致性测试，自带的只有 `sqlite`（`bun:sqlite`，WAL），它要通过一致性测试。原先的 `jsonl` 后台（一个运行一个只追加文件）2026-11-11 由 owner 决定去掉（`operad.md` 决定 13、`operad-slimming.md` 决定 1）。
9. 测试包括固定种子模拟、有界穷举和真的强杀续跑。
10. 插件对象的事实只记变化（2026-11-13 owner 定，方案 b）：对象存储的 `put` 不再每次把整份对象写进事实，只写这次变了的顶层字段（值深比较不同的）和删掉的字段名；对象的当前值照旧整份存在对象表里。起因：`plugins.sqlite` 每天涨约 19MB，几乎全是 `dev` 任务每次状态变化写一份带 brief 的完整快照（2026-11-13 实测 14,703 条、108MB）。读事实的插件（`dev` 的 Answer 分区和 throughput、`chat` 的记录）按变化读；已有的完整快照迁移一次成变化。过程不另存 JSONL（owner 同日问过，选了这条），存储仍只有 `sqlite`（决定 8）。

## 待决问题（未定）

1. 是否允许一个 flow 引用另一个。
2. 默认后台选哪个；和 iOS 的 `api_version` 怎么衔接。
3. 一次运行的预算（时间、费用、尝试次数）放 flow 级还是步骤级。

## 验收

`dev` flow 在新引擎上把一个真实任务从创建跑到等人合并，中途杀掉引擎进程再起来能接着跑；历史能查出每一步；两个存储后台都通过一致性测试；现有 arc 的锁、恢复、幂等相关行为测试按规格通过。
