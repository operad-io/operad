# operad-engine：graph 引擎

- 状态：idea（方向已定：做；节点类型清单与持久化细节未定）
- 涉及 ADR：0048、0001、0040、0011
- 来源：`operad.md`；`research/2026-11-04-agent-autoloop.md`「内核与测试」；`research/2026-11-05-noop.md`「架构」

## 背景

今天 arc 的任务生命周期是写死的一条流程，`[flows]` 只能换参数。要的是一张能设置的 graph：节点是步骤，边是结果，任何一个节点可以指向一个本地 TS 文件做定制。节点会跨天（等人、等 CI、定时复查），所以引擎必须事件溯源、可续跑、幂等。agent-autoloop 的内核（`decide` 纯函数、`evolve` 单写者、追加日志、`why` 查一轮）和 pi durable 的检查点（每个步骤一个可恢复的状态机、`replay: safe` 才重跑）是两份可对照的先例。

## 决定（已定）

1. graph 的结构是数据（一个文件：节点、边、每个节点的类型和参数），节点的定制逻辑是 TS 文件。
2. 引擎是事件溯源的：每次被接受的输入产生一批事实，状态从日志算出，`why <运行>` 一条命令查来龙去脉；日志从不存密钥。
3. 节点声明可重放与否；崩溃后可重放的节点重跑，不可重放的给下游一个"被打断"的结果；连续崩溃到上限就停住等人。
4. 内置节点类型至少有：跑 harness（一次性任务）、跑检查（命令，给 verdict）、问人（结束本轮，答案是事件）、发通道、落地（forge）、等待（`wait_check` 谓词或定时）、来源触发、并行与汇合。
5. 今天的 arc 流水线（worker → commands → mutation → review → ci → human → integration）用内置节点表达为第一张 graph，现有行为测试当它的验收规格。
6. 幂等与熔断进核心：同一来源同一编号的事件只记一次；事件引发的事件带跳数，上限之外只记录不派发；一张 graph 的一次运行连续失败到上限不再重试。

## 待决问题（未定）

1. graph 文件的格式（YAML、JSON、TS 导出一个对象）；是否允许一张 graph 引用另一张。
2. 并发语义：同一张 graph 同一对象一次一运行，还是按节点声明。
3. 存储：SQLite 一个文件，还是文件目录加索引；和 iOS 的 `api_version` 怎么衔接。
4. 一次运行的预算（时间、费用、尝试次数）放 graph 级还是节点级。
5. 模拟与穷举测试要不要像 agent-autoloop 那样做（固定种子模拟、有界穷举、强杀）。

## 验收

第一张 graph 在新引擎上把一个真实任务从创建跑到 `review.awaiting_human`，中途杀掉引擎进程再起来能接着跑；`why` 能查出每一步的事实；现有 arc 的锁、恢复、幂等相关行为测试按规格通过。
