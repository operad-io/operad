- 状态：decided（场景与形状已定；已做的决定移入 ADR，本文件留未做的部分；第三方来源的接入细节未定）
- 涉及 ADR：0030、0031、0011、0025、0032、0038
- 涉及：`operad-conversation.md`；`operad-sandbox.md`；`operad-channels.md`；`operad-plugins.md`；`operad-bot-mcp.md`

## 背景

目标不是 OpenClaw 的市场位置，是自己的几个场景：一个长期存在、手机上随时能聊的 bot；一个个人知识库；每天定时搜集资料。OpenClaw 赢在"真的做事"加零摩擦，输在默认放任（`operad-sandbox.md`）。operad 要在不放任的前提下做到同样的零摩擦：一句话描述需求，agent 写出 flow 或插件，立刻能用。

## 已定但还没做（留在这里，做完移入 ADR）

1. **三个场景，按这个顺序**：长对话（`operad-conversation.md`）；个人知识库（second brain）；每日资料搜集（digest）。后两个是 flow 加 skill，不是新插件，取数据的步骤除外。
2. **知识库是一个插件**：插件叫 `memory`（owner，2026-11-20，原拟名 `brain`），它的 flow 是 `memory:capture`、`memory:review`，skill 也叫 `memory`。它处理信息、归档、找回；存储是一个 Markdown 目录加 git。Obsidian 是 owner 自己的设置，不是 operad 要支持的后台（owner，2026-11-20）：用户可以把这个目录指到自己的 Obsidian 库，operad 不为 Obsidian 做专门的东西，也不要求用户改目录结构。它最关键的两件事是怎么组织、怎么检索；bot 的记忆是它里面的一个保留命名空间。这个插件和记忆的管理以后单独设计，合约上它需要的是外部对象（`operad-contract.md` 决定 3，留在 backlog）、`settings` 和 `secrets`（ADR 0010 D1、D2）。
3. **知识库是三个 flow 加一个 skill**：
   - `memory:capture`：来自 iOS、Telegram 或命令行的一条"记下"事件（文字、链接、转发），agent 按 skill 归档：选目录、写 frontmatter、补 `[[链接]]`、链接的页面抓正文存成附件；写完回一行"存到哪了"。
   - `memory:review`：每天一次 cron，整理 `inbox/`，合并重复，提出三条值得回看的，送一张卡；卡上的动作只有"看过了"和"打开"。
   - 对话里读写：`memory` skill 随 `chat` 的默认访问档一起给 bot，告诉它知识库在哪、怎么写、什么不能删（删除走 ask）。
4. **每日资料搜集是按主题配置的 cron flow** `digest:run`：配置 JSON `{ topic, schedule, sources: [...], deliver: [channel, …] }`，`sources` 的每一项指向一个来源插件（`docs/backlog/operad-channels.md` 的登录与读取一条）：怎么登录、怎么读都归插件，operad 只拿到统一形状的条目。候选插件：`hn`（免费 API）、`rss`（任意 feed）、`reddit`（要注册 OAuth 应用，每个 client 100 次/分，匿名 `.json` 已经关了）、`x`（只剩按量付费，每读一条 $0.005，默认不开，用不用按费用定）、`web`（给定查询词的搜索）。步骤顺序：来源插件的 `fetch` 步骤取条目 → agent 按 skill 去重、排序、写摘要 → 交给知识库插件归档 → 送一张卡（前 N 条，各带链接）。卡上的反应（有用、没用）记成事实，下一天的 prompt 里把最近的反应当资料带上；没有模型替用户改规则。
5. **来源插件不让 agent 碰密钥，也不让来源内容进指令**：条目作为资料给 agent 读（ADR 0009 D1），登录态只在插件自己的 `secrets` 里（ADR 0010 D2）。
6. **不做**：语音、Canvas、摄像头和屏幕一类设备动作、暴露在公网的网关、影子 judge 之外任何"模型替人决定"。按页面结构操作的自动化浏览器不在此列，见 `operad-bot-mcp.md` 决定 10。
7. **费用只做软提示，不硬停**（费用多是估算，订阅登录时尤其如此，按估算硬停不合适）。bot 页显示这个 bot 本期（`period`）的花费，注明是估算；bot 的设置里可以写一个提示线，可不写。本期花费过了提示线，bot 页和这个 bot 的 chat 页显示一行提示，运行照常继续，不成为待处理项，不停下。以后有了准确的费用再议硬停（原来的理由见 `research/2026-11-11-grok-bot.md`）。
8. **不是人当场发起的运行更严**：bot 的定时 flow 和由事件发起的运行按 `docs/backlog/operad-sandbox.md` 的后台运行一条，对外写的动作先问或只存草稿。
9. **技能可以从一个 git 地址导入，导入和更新都要人确认**（`research/2026-11-11-grok-bot.md`「技能和 MCP」）：不做市场，但别家市场里的技能大多是同一种 `SKILL.md` 目录，用户拿地址来就能导入。导入是一个待处理项，展示 `SKILL.md` 全文和文件清单（脚本单独列出），人确认后才进这个 bot 的技能目录；导入的版本钉在一个提交上，不自动更新，更新也是一个待处理项，展示差异。operad 不做搜索和推荐，也不采信市场的扫描结果。`SKILL.md` 头部里别家的私有字段忽略。别家的插件包（技能加 MCP 服务、钩子、子 agent）只导入技能，里面的 MCP 服务按 ADR 0030 D4 单独问，钩子和子 agent 不导入；OpenClaw、Hermes 那种进程内代码的插件不兼容。
10. **技能里的脚本保留，operad 自己永远不执行**（ADR 0030 D7）。还没做的部分：导入来的脚本第一次跑要问（ADR 0025 D3 的精确 argv 加工作目录，再加脚本内容的摘要：内容变了重新问）；不是人当场发起的运行按 `docs/backlog/operad-sandbox.md` 的后台运行一条。不学 Rakazo 导入时丢掉脚本：说明文字本身就能让 bot 去下载并执行代码，防线是访问档，丢脚本挡不住什么，却废掉依赖脚本的技能。壳（ADR 0025 D6）做出来之前，批准一个带脚本的技能等于信任这段代码，确认页要把这一点和脚本清单写明。
11. **chat 和 bot 的用户词**（来自 iOS 设计稿 `radian-ios/docs/design/operad/operad-ios-2026-11-11.html`）：`Allow once`、`Always allow`、`Deny`（工具调用和命令的许可，ADR 0025 D4；`Always allow` 的范围是发起它的 bot 或 repo）；`Continue`（原为费用上限到了以后继续；费用改成软提示后不再用于费用）、`Stop`（停下当前运行）；`I logged in`、`Log in again`（站点登录，`operad-bot-mcp.md` 决定 13、14；`I logged in` 只是提醒 bot 去看，不代替登录）；`repo`（chat 父对象类型的标签，和 `bot` 并列）；`period`（费用的统计周期）。`Review`、`approve`、`reject` 已在 ADR 0030 D4。说话人不是新词：harness 名（claude、pi、radian）只决定用哪个 agent，对话里显示的是 ADR 0026 D12 的称呼。
12. **bot 页是这个 bot 的设置页**：上面是称呼、harness、模型、工作目录、本期花费和上限、技能、MCP 服务、登录过的站点；能直接改的项走设置接口（ADR 0017），技能和 MCP 服务的增加和更新走 `Review`。bot 页上没有 Chat 按钮，新建 chat 只从 chat 的入口进（ADR 0028 D5）。`bot` 不占自己的 tab，bot 列在设置下面（ADR 0018 D3）。
13. **bot 写记忆不用人批准**（owner，2026-11-20）。事后靠知识库的 git 记录和 `memory:review` 的差异来看。必须遵守的规则不进记忆这一条不变，它们的改动仍走提议（ADR 0030 D4）。
14. **记忆的索引作为消息的附注带进去，不进系统提示，也不在会话内冻结**（owner，2026-11-20；Linger 的做法，见 `research/2026-11-19-linger.md`）。
   - 新会话的第一条消息和压缩后的第一条消息带上完整索引。
   - 之后每次回复前比较索引文件的哈希；被别处改过（同一个 bot 的另一个 chat、定时运行、整理步骤），就在下一条消息上附整份新索引，不只附改动的行。这个 chat 自己写的不重发。
   - 索引的上限从 8,000 字符左右起，用起来再调。
   - 用户给 bot 的长期指令那个文件同样处理。
   - 理由：一个 chat 一直续用同一个 harness 会话（ADR 0026 D3），可能持续好几天，冻结会让整理改正的笔记晚几天生效；每次重写系统提示会让提示缓存失效；`chat:reply` 本来就由 operad 拼提示，附注在消息上对 claude、pi、radian 都一样。
16. **目录：记忆按 bot 分，知识库叫 `wiki`，所有 bot 共用一份**（owner，2026-11-20）。
   - 每个 bot 的记忆在它自己的目录下：`~/.operad/bot/<bot>/memory/`。记忆不在 bot 之间共享。
   - 默认 bot 改用 `~/.operad/bot/default/`，和其他 bot 平级，不再是它们的父目录（现在 ADR 0030 D2 让默认 bot 直接用 `~/.operad/bot/`，它的目录因此包含其他 bot 的目录，能读到它们的记忆）。已有的默认 bot 目录要迁移一次；改 ADR 0030 D2 和做迁移是同一个任务。
   - 知识库的笔记在一个可设置的目录，默认 `~/.operad/wiki`，中文叫"知识库"；用户可以把它指到自己的笔记库（比如 Obsidian 库）。哪个 bot 能写它由各自的访问档决定（ADR 0030 D1）。名字取自 Karpathy 的 LLM wiki：模型维护的笔记、一页一行的索引、整理时查矛盾和过期。
   - `wiki` 是 owner 2026-11-20 批准的用户词。
17. **bot 的记忆不加双链和反向链接**（owner，2026-11-20）。保持现在的做法：`memory/index.md` 用相对 Markdown 链接指向主题笔记。理由：记忆小、按 bot 分、索引常驻，索引加搜索够用；同类产品在记忆层也都不做双链（`research/2026-11-20-wiki-links.md`）。双链和反向链接只在知识库这一层考虑。知识库的链接表已定并已做（ADR 0038 D8）：建全文索引时解析 `[[ ]]` 和相对 Markdown 链接，存在同一份 `search.sqlite`，按 Obsidian 的规则解析目标，没解析到的保留。bot 的查询入口已定并已做（读一篇笔记时带上反向链接，见 ADR 0038 D8）；整理时的链接检查也已定并已做：整理前从链接表算出断链、孤儿、被三个以上笔记链接的缺页和未链接的提及，非空的列表进整理的提示，链接检查本身不拦运行，也不进待处理卡。
   - "反向链接 / backlinks" 是 owner 2026-11-20 批准的用户词（知识库这一层用）。
   - "Note / 笔记"（知识库里笔记这一对象类型的名字）是 owner 2026-11-20 批准的用户词。

## 记忆和知识库：提议（2026-11-15，owner 未定）

上文第 2 条说"这个插件和记忆的管理以后单独设计"。这一节是那份设计的起点，出自 `research/2026-11-15-memory.md` 的调研，由 research consultant 提出。每一条都还不是决定；owner 定了的移到上面的"已定但还没做"。2026-11-20 owner 定了写入不用批准、全文索引第一版就带、索引作为消息的附注带进去、整理先检查再问、记忆按 bot 分而知识库叫 wiki 共用一份（第 8 条的范围因此已定），见上文「已定但还没做」第 13 到 16 条；本节其余各条仍是提议。

1. **记忆的布局是三层**，都在知识库里那个保留的命名空间下：
   - 一个有上限的索引，每次运行都进上下文；
   - 只追加的每日记录；
   - 按需读的主题笔记，索引里一行一条指向它们。
   用户给 bot 的长期指令单独一个文件，每次运行都加载。OpenClaw、Claude Code、NanoClaw、Letta、Anthropic 的文章都是这个形状。
2. **必须遵守的规则不进记忆**。它们留在 bot 的说明和访问档里，改动走提议（ADR 0030 D4）。记忆只帮助回想；Codex、Copilot、Grok Bot 都这样分。
3. **记忆只放查不到的**：偏好、纠正、验证过的规则。operad 里已经有的（计划、任务、历史）和知识库里已经有的笔记，存指针，不抄一份。
4. **bot 当场写笔记，只给很轻的指引**：`memory` skill 告诉 bot 记忆是干什么用的，不规定怎么记。跑在较弱模型上的 bot 要有"先读记忆再回答"的提示。
6. **来源内容触发的写入要标来源**（细化上文第 5 条）。一次运行读过网页、来信、来源插件的条目之后写下的笔记，标为"来自不可信内容"，不进每次加载的索引，整理时也不提升。不做 OpenClaw 那种文件级的排除：知识库就是要让人用自己的编辑器（比如 Obsidian）直接改的，它的校验在人改过文件后会把整个文件永久排除。
   2026-11-20 已做（T-0585）：`memory` 插件把 frontmatter 里 `untrusted: true` 的笔记从 `memory/index.md` 里剔掉，笔记本身保留；这个标记由 bot 按 `memory` skill 自己写。
   还缺：一次运行读过哪些材料没有被记下来。harness 读网页、邮件不算 material，MCP guard 只把返回文本标注为 material、不按运行入账，所以 operad 还不能自己判断一次运行是否读过不可信内容，`memory` skill 里这一条只能靠 bot 自己标。等有了按运行的材料清单再自动标。
7. **`digest:run` 记下发过什么**（细化上文第 4 条）。下一天的 prompt 除了最近的反应，还带上最近发过的条目，避免重复推送。
8. **范围按 bot**；多人场合（Telegram 群）不注入个人记忆。定时和事件发起的运行读它的 flow 需要的那部分，它写的东西按第 6 条处理。
9. **压缩前先落盘**：见 `operad-chat-next.md` 第 2 条。
10. **整理的费用提示**（research consultant 的提议，2026-11-20，owner 未定）。都是估算，都不拦运行：
   - 卡上，跑之前：写这次要处理的量（多少条新笔记、多少个 chat 的记录要核对）和最近几次整理的平均花费；不预估这一次。没有历史时只写量。
   - 跑完之后：没开自动的，结果卡上写这次的花费和差异摘要；开了自动的不送卡，只在改了东西时发一行通知，带花费。
   - bot 页的本期花费里把整理单列一行，和 chat、定时任务分开。
   - 自动模式下，单次整理的花费超过最近平均的若干倍（比如 3 倍），下一次改回送卡询问，卡上说明原因；当次照常跑完。
   - harness 不报费用时只显示 token 数，不显示金额。

   另外两条同样是提议：核对只做增量（只核对上次整理之后新写或改过的笔记，只对着这段时间的 chat 记录），全量查矛盾、过期和孤儿一周一次；chat 正在回复时不跑整理，避免两边同时写同一个文件。

## 定时任务（owner，2026-11-17；定时 prompt 已做，见 ADR 0030 D10、D11）

定时 prompt、它的管理、后台规则、补跑和完成通知已经做进 bot 插件；在对话里创建、编辑和删除定时 prompt 也是提议。这里留下还没做的一类：

1. **定时 flow**：到点启动一个已加载的 flow，带固定参数。底层就是 `triggers.json` 里带 `schedule` 的 cron 规则（ADR 0032 D5），客户端给它一个列表和表单；结果在它的历史里。

## 跟进（owner，2026-11-22 全部已定；未做）

来源：《Building always-on agents》（`claude.com/resources/articles/building-always-on-agents`，2026-11-13）把定时器分成两类：schedule 是用户定的周期任务，follow-up 是 agent 给自己定的一次性期限。operad 只有前一类（ADR 0030 D10、D11，ADR 0032 D5），bot 做不了"两小时后再看一眼"或"周五提醒我"。

已定（owner，2026-11-22）：

1. **用户词是 Follow-up，中文"跟进"**（owner 2026-11-22 批准，中英文都已确认）。
2. **bot 在 chat 里定的跟进直接生效，不走提议**。这和定时 prompt 不同（ADR 0030 D11 仍是提议）。理由（research consultant 的理解，owner 未逐条确认）：跟进是一次性的，到点只是回到同一个 chat 再说一句；对外写仍受 ADR 0025 D10 约束。

已定（owner 2026-11-22，按 lead 的建议；原是 research consultant 的提议）：

3. **跟进到点回到定它的那个 chat，续原会话**，不像定时 prompt 那样开新 chat（ADR 0030 D10）。文章的规则：续旧事的事件恢复原会话，其余开新会话。
4. **到点的这次回复是后台运行**（ADR 0025 D10），事件来源是 `bot`；补跑按 ADR 0032 D11，晚了就在提示里加一行说明原定时间和晚了多久。
5. **一条跟进有：到点时间、一句要做什么、所属 chat**。bot 页和 chat 里能看到没到点的跟进，人可以取消。上限：一个 chat 同时最多 5 条没到点的跟进，最远 30 天。bot 定跟进用一个只给 agent 用的命令（`bot:follow-up`），不是用户词；bot 页和 chat 里显示跟进的界面若要新词，另批。
6. **bot plugin 自己当来源**，和定时 prompt、夜间整理一样（ADR 0030 D10、D13），不进内核。
7. **定时 prompt 可以安静结束**：回复表示"没有要报告的"时，这次不跑通知命令，只记最近一次结果。现在每次触发都通知（ADR 0030 D10）；夜间整理已经是"只有改了东西或失败才发"（ADR 0030 D13）。文章：一次运行的结局是发消息、什么都不发、挂起问人三种，先安静。
8. **记下已经告诉过用户什么**：定时 prompt 每次开新 chat，不知道上一次发过什么。把上文「记忆和知识库：提议」第 7 条（`digest:run` 记下发过什么）推广到所有定时 prompt：下一次的提示带上这个条目最近几次的结果摘要。
9. **跨多次运行的事各写一个进度文件**：`memory` skill 加一句，进度文件放在 bot 的 `memory/` 下，索引里留一行。只改 skill 文本。

顺序：先 7 和 8（定时 prompt 安静结束、带上最近结果），再 3 到 6 的跟进（9 随它），最后桌面和 iOS 显示、取消没到点的跟进。

## 顺序

`operad-conversation`（ask 闭环 → `chat` 基础插件加 `dev:chat` → `bot` 插件的 bot 对象加 `bot:chat` → app 的输入框）→ `operad-sandbox` 第一版的其余部分 → Telegram 通道 → `memory` 三个 flow → `digest`（先 `hn` 和 `rss`，再 `reddit`，`x` 看费用）。

## 验收

用它替掉自己的 OpenClaw 场景：连续两周无人值守，每天的 digest 按时到 Telegram 和 iPhone，知识库里每天多一个 digest 文件；两周内 `memory:capture` 用过至少 20 次，没有一次需要人去修权限或清理副作用；三个 flow 都是在新引擎上用 flow 文件加 skill 表达的，没有改内核。
