# PiBot：一个建在 pi 上的桌面个人助理，和 operad 首次使用方向的对照（2026-11-21）

owner 问的问题：研究一下 https://github.com/w01fb0ss/PiBot。它和 `docs/backlog/operad-first-run.md`（P-0122）定的方向几乎重合：只装桌面应用、内置 pi、界面里登录、默认落在一个 bot 的对话里。这里记它怎么做的，以及对 P-0122 有什么用。

出处：源码 `c923b02d`（v0.0.3，2026-11-21 的浅克隆，只看得到一个提交）的一次只读调查，没有构建也没有运行。标 **抽查** 的是另外核对过原文件的；标 **推断** 的不是直接读到的；其余只出自那一次调查，没有逐条复核。路径都相对它的仓库根。最后两节是判断，不是决定。

## 一览

- Electron 桌面应用：一组有名字的 bot 在本机干活，单聊或群聊；另有 Android 应用、自建中继、别的机器上的 runner。Apache-2.0。
- 仓库 2026-11-21 公开，版本 0.0.3（抽查：`apps/desktop/package.json`）。非测试的 TS/TSX 约 57 万行，公开的单元测试约 50 个文件；`.gitignore` 排除了 `internal/` 和 `tests/eval/`，多数测试可能在私有仓库（推断）。
- macOS 安装包没有签名和公证（`electron-builder.yml`：`identity: "-"`、`notarize: false`），文档让用户点"Open Anyway"。
- Windows 上命令没有隔离，每条都要批准；README 说"命令在沙箱里跑"。

## 1. 怎么内嵌 pi

- **当依赖，不安装**：`@earendil-works/pi-coding-agent` 和 `pi-ai` 钉在 1.4.0（抽查：`packages/agent/package.json:21-22`）。只有 `packages/agent` 引用 pi；不调用机器上的 `pi` 命令。不用 pi-durable。
- **入口和 operad 一样**：`createAgentSession`、`ModelRuntime.create`、`SessionManager`（`packages/agent/src/runtime/runtime-parts/runtime-session.ts:279`、`runtime.ts:168`）。pi 的内置工具关掉，换成它自己的工具；权限检查是 pi 扩展的 `tool_call` 钩子（`packages/agent/src/extensions/pibot-policy.ts`），和 ADR 0023 的做法相同。
- **和用户自己的 pi 完全隔离**：启动前删掉所有 provider 的环境变量和 `PI_*`，设 `PI_OFFLINE=1`、`PI_TELEMETRY=0`、`PI_CODING_AGENT_DIR=<数据目录>/pi`（抽查：`packages/agent/src/core/env.ts`）；一个探针断言已有的 `~/.pi/agent/auth.json` 不被读也不被改（`packages/agent/scripts/probe.ts:360-415`）。
- **进程**：界面进程起一个后台 owner（托盘、钥匙串、单实例锁），owner 用 `utilityProcess.fork` 起"brain"，pi 在 brain 进程内跑（`apps/desktop/src/main/brain/brain-process.ts:31`）。
- **存储**：pi 的 JSONL 会话文件在 `<数据目录>/bots/<id>/sessions`；其余在一个 `node:sqlite` 库里，171 个只追加的迁移。
- **给 pi 打补丁**：用 pnpm 的 `patchedDependencies` 改 pi-coding-agent 和 pi-ai 发布包里的文件（加入口、OpenRouter 的费用、ChatGPT OAuth 回调的状态检查、回调页面的文案），`@anthropic-ai/sandbox-runtime` 也打了补丁（`pnpm-workspace.yaml:29-34`）。

## 2. 首次登录和凭据

**引导的模型一步**（`apps/desktop/src/renderer/features/welcome/ModelStep.tsx`），四张卡片：

1. 推荐路线，按界面语言预选：中文是 DeepSeek API，英文是 OpenRouter（`RecommendedSetup.tsx:31-55`）。用户贴一个 key，"Save & test"，模型已经选好。
2. ChatGPT 订阅登录（有一个发布开关）。
3. 本地 Ollama：`GET http://127.0.0.1:11434/api/tags`，1.5 秒超时；三种状态：没检测到、在跑但没有模型、再检查一次（`packages/models/src/brain/catalog/ollama.ts`）。
4. "Use my API key"：分组、可搜索的 provider 列表。

- "Continue" 在选好一个配置过的模型之前是禁用的。选定后一次调用 `settings.set {defaultModel, initializeMainBot: true}`：校验模型可用，并在一个事务里写成主 bot 的默认模型（`packages/models/src/brain/settings/model-settings.ts:62-115`）。
- 没有内置模型，首次运行不下载模型。模型一步里有设置网络代理的链接。

**用 pi 的登录接口**：只有 ChatGPT 订阅这一条走 `runtime.login(id, "oauth", interaction, …)`（抽查：`packages/agent/src/runtime/runtime-parts/runtime-models.ts:33`）。`AuthInteraction` 由服务端的 `LoginFlow` 实现（`packages/models/src/brain/auth/provider-login.ts`）：

- `notify({type:"auth_url"})`：先校验地址（域名必须是 `https://auth.openai.com`，回调必须是 `http://127.0.0.1:<port>/auth/callback`），再由宿主打开浏览器，并向界面发一步 `browser`。
- `prompt({type:"manual_code"})`：退路，浏览器没跳回来时让用户粘贴最后的跳转地址，按预期的 state 校验。
- 300 秒超时，可取消；界面通过 `providers.login`、`cancelLogin`、`loginStep`、`loginInput`、`authState` 这几个调用驱动。
- 回调服务跑在 brain 进程里，`127.0.0.1:1455`，被占用就换端口（`packages/agent/src/auth/chatgpt-callback.ts`）。

**支持哪些订阅登录**：只有 ChatGPT，两条路。一条是它自己写的官方"Sign in with ChatGPT"（PKCE、动态注册客户端、校验 ID token）；另一条是 pi 原有的 Codex 登录，用的是 Codex CLI 的公开客户端身份。Claude 订阅明确拒绝：任何 `sk-ant-oat` 的值抛 `claude_subscription_unsupported`（抽查：`packages/agent/src/auth/claude-subscription.ts`），用户文档说 Anthropic 不允许 Claude 订阅登录第三方应用。其他 OAuth provider 一律 `subscription_unsupported`。

**凭据存哪**：自己的加密库，密文在 SQLite 里，用 Electron `safeStorage`（macOS 钥匙串、Windows DPAPI、Linux libsecret）加密，owner 进程经宿主接口提供给 brain（`packages/models/src/brain/auth/provider-auth.ts:56`）。它实现了 pi 的 `CredentialStore` 接口，pi 的 `auth.json` 不用。钥匙串不可用时拒绝保存。

**不复用已有登录**：不读 `~/.pi`、Claude Code、Codex 的登录。唯一的复用是环境变量：检测到某个 provider 的环境变量时显示"Environment variable detected"并给一个"Import"按钮（`packages/models/src/brain/catalog/rpc.ts:77-96`）。

**key 不给 agent**：每次调用用 `setRuntimeApiKey` 注入；日志和 RPC 过一个脱敏器；界面只看得到 4 个字符的提示；命令沙箱拒绝访问凭据目录和别的 AI 工具的配置目录。

**令牌刷新**：每 60 秒检查一次，过期前 3 分钟刷新；`invalid_grant`、401、403 判为登录失效并请用户重新登录，超时和 5xx 保留凭据（`packages/agent/src/auth/oauth-refresh.ts`）。每个 provider 一个 key，每个安装一个 ChatGPT 身份。

## 3. 首次引导

五步（`welcome/index.tsx`）：介绍和语言外观；选模型；选一个起步的 bot（可跳过）；macOS 的系统权限（可"Not now"）；见主 bot。

- 主 bot "Pi" 在 brain 启动时就建好（`bots.ensureMainBot`），不能删。没有默认的群。
- 最后一屏给四条起步建议，按钮"Chat with Pi"，落在和主 bot 的对话里。
- 屏幕录制权限要重启，所以流程只记住重启后要回到的那一步。
- 发第一条消息之前最少要做的：贴一个 key，或选一个 Ollama 模型，或登录 ChatGPT。

## 4. 打包和运行

- Electron 44.7.0。安装包里带 ripgrep、一份钉了 SHA-256 的 Node 26.11.1（跑所有子进程）、沙箱的二进制、macOS 电脑操控的驱动，Windows 上带 MinGit。
- 首次运行不下载模型、运行时或浏览器。按需、经用户同意、钉 SHA-256 才下载的：Python 技能用的 uv、Codex 和 Claude 的 ACP 适配器。
- 更新：`electron-updater`，下载和安装等用户确认。
- 关窗后 owner 和 brain 继续跑，托盘里有"Quit completely (routines stop too)"；开机启动有三档。
- 一个数据目录一个 owner。版本是应用版本加构建哈希，旧的 owner 被要求停下并排空。数据库比应用新时报 `database_newer_than_app`，界面说"更新应用再重试，不要删除数据"（`packages/storage/src/database/database.ts:95`）。
- CLI 和桌面端不共用数据目录：CLI 拒绝桌面端的目录。

## 5. 许可、权限、沙箱

- 一个策略引擎（`packages/policy`，约 1.2 万行）：请求按类别区分（跑命令、读写文件、网页、连接器、对外发送、电脑操控等），结果是允许、询问、拒绝，带风险级别和一条解释，解释用在卡片的"为什么问我"上。
- 11 个类别各设 never、ask、always；bot 可以覆盖，群只能收窄。
- "Always allow" 的范围按目标、文件夹、域名、程序等区分；连接器工具和发送目标的授权按定义的 SHA-256 钉住，定义变了授权失效。
- 每个对话可以开 YOLO，但危险动作、以用户名义发送、付费生成不跳过。
- 沙箱用 `@anthropic-ai/sandbox-runtime`：macOS Seatbelt，Linux bubblewrap；写只限工作目录，网络走允许名单。
- 权限矩阵测试：108 个有代表性的请求乘以 3 个平台和 3 个级别，对照一张人工审过的期望表，是 `check` 的一部分（`tools/dev/policy-matrix/`）。

## 6. 群聊、中断后继续

- 群里有协调者：复杂的活先出一张"执行计划"卡（步骤、负责人、依赖、能并行的、预计费用），用户点开始或修改。交接是结构化的，带期望产出和完成条件，由程序检查，不合格自动退回。
- 并行的开发步骤各在一个 git worktree 里，协调者审过、用户批准后合并。
- 应用重启后运行不自动恢复，被打断的运行显示"Continue"。恢复时保留原来的预算和工具日志，并告诉模型哪些调用结果未知（`packages/brain/src/runtime/queue/resume-service.ts`、`runtime/tools/journal/journal.ts`）。

## 7. 其他

- 定时和触发的任务、待办、分范围的记忆（改动走提议）、只读的 Obsidian 和 Notion 知识库、`SKILL.md` 技能（导入先预览，更新按文件摘要出差异）、MCP（可以从 Claude Code、Codex、Cursor、pi、OpenCode 的配置里只读扫描后导入，导入后不自动给任何 bot）。
- 手机：Android，扫码配对加核对安全码，Noise 加密，局域网直连、NAT 穿透、中继三条路。
- 编辑器经 ACP 接入；它也能把 Codex、Claude Agent、Cursor、OpenCode 当成"外部 agent"的 bot，只检测 `PATH` 和常见安装目录。
- 写代码：每个目录最多 3 条自动检查命令，由 bot 提议、用户确认；改动面板、另一个 bot 的只读评审、提交（不 push，没有 PR）；改文件前的字节快照，可按消息恢复。

## 判断：对 P-0122 有什么用

1. **登录一步里选定默认模型**。P-0122 留着"没有 pi 登录的机器上默认模型选哪个"没定；PiBot 的答案是登录这一步由用户选定，一次调用里校验并写到主 bot 上。建议 T-0678 照这个做。
2. **推荐路线按语言预选**。一条最省事的路预先选好，用户只贴一个 key。预选的模型 id 写死会过期，要有一个能更新的来源。
3. **`ModelRuntime.login` 接到界面的形状可以照做**：地址先校验再由宿主打开；浏览器没跳回来时粘贴跳转地址；有超时，可取消。它的回调服务跑在后台进程里，说明这条路可行；Bun 子进程里是否一样，T-0678 的探针仍要自己验证。
4. **订阅登录的条款要先定**。PiBot 只做 ChatGPT，明确拒绝 Claude 订阅。operad 的 ADR 0024 也记着 Anthropic 不允许第三方在自己的产品里提供 claude.ai 登录。operad 在自己的界面里引导某个 provider 的订阅登录，和用户自己在 pi 里登录不是一回事。T-0678 开工前要 owner 定：登录界面提供哪些 provider 的订阅登录，哪些只给 API key。
5. **凭据位置上两边相反**。PiBot 用自己的加密库，从不碰 `~/.pi`；P-0122 定的是继续写 `~/.pi/agent/auth.json`。operad 的用户多半已经在用 pi，共用登录少登一次；代价是 operad 装的 pi 和用户的 pi 两个版本读写同一份文件（P-0122 已记为未核实）。不建议现在改，但这条风险要在 T-0677 或 T-0678 里验证掉。
6. **环境变量里的 key 给"导入"按钮**，不默默继承。
7. **数据比程序新时的报错**：明确说"更新，不要删数据"。对应 P-0122 里"用新的并提醒"还没核实的那个细节。
8. **被打断的运行给"继续"**，并告诉模型哪些调用结果未知。和 `2026-11-19-pi-durable.md` 建议先补的缺口是同一个思路，比 pi-durable 轻。

## 判断：不该照搬的

- 给 pi 发布包里的文件打补丁：每次升级都要重做。要入口就向上游提。
- 用 Codex CLI 的客户端身份做 ChatGPT 登录：有条款风险。
- CLI 和桌面端各用各的数据目录：operad 要共用一个 home。
- 第一版的范围：手机、中继、电脑操控一起上，公开的测试很薄。P-0122 的范围保持窄。
- 不签名的 macOS 安装包。

## 没有验证的

- 除标"抽查"的四处外，其余都没有对照原文件复核。
- README 说检查点恢复只在 macOS，上面读到的代码三个平台都有，差在哪没查到。
- 安装包的实际大小；发布构建是否另外签名。
- 它的"Sign in with ChatGPT"动态客户端是否得到 OpenAI 认可，只有代码注释这么说。
- 私有仓库里的测试有多少。
